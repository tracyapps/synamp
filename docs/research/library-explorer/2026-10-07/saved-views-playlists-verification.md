## Implementation and limits

Frontend source: `library-view-state.ts`, `useLibraryView.ts`, `SavedLibraryViews.tsx`, `FilterPlaylistDialog.tsx`, `LibraryExplorer.tsx`; `App.tsx` recognizes hash query state and refreshes playlist nodes after creation. Table columns stay in their independent presentation preference. Filter typing replaces one history entry; saved-view open, reset and artist drill-down create checkpoints. Unsupported state blocks snapshot/save actions until recovery; it is never silently broadened.

Backend source: shared song selection in `library/explore.ts`, `library/explorer-selection.ts`, `PlaylistStore.createSnapshot`, and the two authenticated routes in `index.ts`. The receipt is opaque, server-owned, immutable and held in memory: 10-minute lifetime, at most 32 receipts, at most 100,000 selected IDs. Restart/expiry/eviction requires preview again; idempotency is limited to the retained receipt lifetime. This is a manual playlist, not an automatically updating smart playlist. Selection uses song-level matching; a displayed matching album or artist does not imply every contained song matches. No client IDs are accepted on confirmation.

Browser checks use a 210-record synthetic export (205 Bulk songs plus five mixed-credit/Unicode/folder examples), loopback Brain/static servers and isolated playlist/event/session paths in an OS temporary directory. Metadata, UI, storage and API were exercised; no music playback, NAS/device timing or actual owner library write was tested. The full fixture, scratch server, CLI scripts and logs are retained to reproduce this local check. The scripts run from the repository root, emit screenshots under `output/playwright`, and use the task's scratch CLI config/session. Adapt their absolute repository/config paths and reserve scratch ports before running; never reuse live stores. Earlier harness failures were selector ambiguity or a relative API URL, corrected before these passing receipts.

Remaining: nested pivot hierarchy LE03; searchable annotations/favorites LE08; reviewed virtual releases LE04 and stable multi-artist identities LE05; Galaxy paths/layouts/cards LE07/LE10. Real deployed tester onboarding/smoke checks, backup import/account sync, physical device and screen-reader validation remain unverified. This receipt does not authorize live-system changes. These operational records and private paths must remain outside a future public knowledge-base export.

Final research integrity: `pnpm research:build` and `pnpm research:check` verify all 321 original archive hashes and catalog links; changed-file whitespace checks pass.
